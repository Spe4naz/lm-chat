# LM Chat

Android-клиент (а также приложение для Windows) для общения с моделями,
запущенными в **LM Studio** на вашем компьютере. Работает по локальной сети,
без облака и без аккаунтов.

Написан на Flutter, собирается в один APK.

Плагин для доступа модели к компьютеру: [lm-computer](https://github.com/Spe4naz/lm-computer).

## Возможности

- Стриминг ответов (SSE) с индикатором набора, живой статистикой и кнопкой
  «Стоп».
- Markdown: заголовки, списки, таблицы, цитаты, блоки кода с копированием.
- Изображения для vision-моделей: до 4 картинок на сообщение, встроенный
  просмотр и сохранение в истории. Через мостик нужен обновлённый
  `lms_gpu_bridge.py` (`BRIDGE_MAX_BODY` по умолчанию 32 МиБ).
- Блок «Размышления» для reasoning-моделей (`reasoning_content`).
- История чатов на устройстве, поиск по чатам и сообщениям, закрепление,
  архив, переименование, удаление, очистка.
- Редактирование сообщений пользователя и повторный ответ с этого места.
- Продолжение готового ответа с места остановки.
- Голосовой ввод: микрофон в поле сообщения, распознавание речи на телефоне,
  язык следует языку интерфейса, текст вставляется в позицию курсора.
- Формат ответа: обычный текст, JSON-объект, JSON по схеме (LM Studio
  превращает её в грамматику для GGUF) или GBNF-грамматика.
- Библиотека промптов: встроенные шаблоны системного промпта и свои.
- Выбор светлой, тёмной или системной темы.
- Оформление: встроенные шрифты Inter и Manrope, размер текста 90–120%,
  JetBrains Mono для блоков кода; настройки применяются сразу. Плотность
  интерфейса переключается между обычной и компактной. Можно импортировать
  собственный TTF-шрифт — файл хранится только на устройстве.
- Адаптивный интерфейс: постоянный сайдбар с чатами на Windows, drawer на
  телефоне, ограничение ширины текста на больших экранах. Сайдбар
  сворачивается кнопкой или `Ctrl+B`, его ширина меняется перетаскиванием
  края и сохраняется между запусками.
- Заголовок окна Windows следует светлой или тёмной теме приложения.
- Перенос настроек между устройствами: экспорт и импорт профиля JSON с
  серверами, параметрами генерации, оформлением и своими промптами. API-токены
  и токены мостика в профиль не попадают. Собственный TTF-шрифт остаётся на
  исходном устройстве — в профиль переносится только выбор встроенного шрифта.
- Подсветка синтаксиса в блоках кода Markdown для популярных языков
  (Dart, Python, JavaScript/TypeScript, SQL, JSON, shell и других).
- Горячие клавиши Windows: `Ctrl+N` — новый чат, `Ctrl+F` — поиск по чатам,
  `Ctrl+B` — свернуть сайдбар, `Ctrl+,` — настройки, `Esc` — остановить
  ответ.
- Русский и английский интерфейс, системный язык или выбор вручную.
- Индикатор «нет связи» с сервером и кнопка повторного подключения.
- Импорт истории из JSON (полный экспорт или отдельный чат).
- Сохранение вариантов ответа: при повторной генерации предыдущий ответ
  остаётся на телефоне, к нему можно вернуться стрелками `‹ ›` под ответом
  или через список «Все варианты».
- Редактирование ответа: изменённый текст становится текущим, прежний
  сохраняется как вариант, ответ помечается «изменено».
- Выбор модели из `/api/v1/models` с метаданными: параметры, квантование,
  максимальный контекст, размер, отметка «в памяти».
- Настройки запуска модели: контекстное окно (пресеты и своё значение),
  «Загрузка модели по требованию», TTL автовыгрузки, передача на GPU
  (0–100%), Flash Attention, KV-кэш на GPU, eval batch size. Кнопки
  «Загрузить/Перезагрузить» и «Выгрузить».
- Необязательный мостик к `lms` на сервере: включается одной кнопкой,
  принудительная загрузка всех слоёв на GPU (`--gpu max`), оценка памяти до
  загрузки.
- Генерация в фоне: foreground-сервис не даёт Android заморозить ответ, а
  задания мостика продолжают считать его на сервере даже после сворачивания,
  потери сети или закрытия приложения.
- Статистика ответа: время до первого токена, средняя скорость `tok/s`,
  общее время генерации, токены запроса и ответа. У каждого сохранённого
  варианта свои цифры.
- Остаток контекста над полем ввода: `Контекст: осталось N из M` с полосой
  заполнения и предупреждением при остатке <20% и <10%.
- Параметры на чат: temperature, top_p, max_tokens, system prompt, формат
  ответа.
- Дополнительное сэмплирование: top_k и repeat penalty, а также пресет
  рекомендованных значений для Gemma (1.0 / 0.95 / 64 / 1.1).
- Настройки запуска задаются отдельно для каждого чата и как значения
  по умолчанию для новых чатов.
- Несколько серверов (LM Studio, Ollama, любой OpenAI-совместимый endpoint).
- Автообновление через GitHub Releases: проверка версии, скачивание с проверкой
  SHA-256 и установка APK или Windows-установщика.
- Несколько чатов могут генерировать ответы одновременно.
- API-токены и токены мостика хранятся в системном хранилище (Android
  Keystore / Windows Credential Manager), а не в JSON. Если системное
  хранилище недоступно, они остаются только в памяти до перезапуска.
- Проверка подключения и понятные сообщения об ошибках.
- Диагностика: экран с последними запросами, ошибками, состоянием сервера и
  копированием лога.
- Экспорт чата или всей истории в JSON, отдельного чата или всей истории в
  Markdown, статистики в CSV; копирование чата в буфер. Можно выбрать несколько
  сообщений и экспортировать или скопировать только их — без остального чата.
  API-токены и токены мостика в экспорт не попадают.
- Импорт истории из JSON с предпросмотром и выбором чатов.

## Настройка LM Studio на Ubuntu

1. Откройте **Developer → Start Server**. Порт по умолчанию — `1234`.
2. Включите **Serve on Local Network**.
3. При необходимости включите **Require Authentication** и создайте API-токен.
4. Узнайте IP компьютера:

   ```bash
   hostname -I
   # или
   ip -4 addr show | grep inet
   ```

   Нужен адрес вида `192.168.1.50` (не `127.0.0.1`).
5. Если включён файрвол, разрешите порт:

   ```bash
   sudo ufw status
   sudo ufw allow 1234/tcp
   ```

6. Телефон и компьютер должны быть в одной Wi-Fi сети.

Проверка с самого Ubuntu:

```bash
curl http://localhost:1234/v1/models
curl http://192.168.1.50:1234/v1/models
```

Вторая команда должна работать — если нет, сервер слушает только localhost
или порт закрыт файрволом.

### Ubuntu без монитора (headless)

LM Studio можно запускать как сервис через `lms`, без графического интерфейса:

```bash
lms server start --bind 0.0.0.0 --port 1234
lms load <имя-модели>
lms server status
```

`--bind 0.0.0.0` — то же самое, что переключатель «Serve on Local Network».
Автозапуск при загрузке системы настраивается через systemd (см. раздел
«Run LM Studio as a service» в документации LM Studio).

Полезно закрепить адрес: сделайте DHCP-reservation в роутере или настройте
статический IP в netplan, иначе после перезагрузки адрес может измениться.

### Если сервер на Windows

Отличия минимальны: IP смотрится через `ipconfig`, а порт 1234 нужно разрешить
в брандмауэре Windows для профиля «Частная сеть» (или добавить правило
`New-NetFirewallRule` для TCP 1234).

В приложении укажите адрес **без** `/v1`:

```
http://192.168.1.50:1234
```

HTTP разрешён только для локальных адресов (192.168/16, 10/8, 172.16/12,
100.64/10 для Tailscale, `localhost`, `.local` и т. п.). Для внешнего
endpoint нужен HTTPS.

Проверка из браузера телефона: `http://192.168.1.50:1234/v1/models`.

## Настройки запуска модели

Открываются иконкой памяти в шапке чата или через меню «Запуск модели».
Те же настройки есть в «Параметрах чата» и в разделе «Запуск модели по
умолчанию» на экране настроек.

- **Контекстное окно** — пресеты от 1024 до 262144 токенов и своё значение.
  Список ограничивается `max_context_length` выбранной модели. Больший
  контекст требует больше памяти.
- **Загрузка модели по требованию** — при отправке сообщения приложение не
  проверяет память и не загружает модель заранее, а сразу стримит ответ;
  LM Studio загружает модель сама. Если выключено, приложение перед первым
  сообщением проверит `/api/v1/models` и при необходимости загрузит модель
  с выбранными параметрами (в сообщении появится «Загружаю модель…»).
- **Автовыгрузка простоя (TTL)** — `ttl` в секундах передаётся вместе с
  запросом на генерацию; `Сервер` означает настройку LM Studio (по умолчанию
  60 минут).
- **Передача на GPU** — доля модели, выгружаемая в видеопамять: `CPU` (0%),
  25%, 50%, 75%, 100% или `Авто` (значение LM Studio). Если у сервера указан
  мостик (см. ниже), значения превращаются в `--gpu off`, `--gpu 0.50`,
  `--gpu max` и выполняются через `lms`; `Авто` означает «не передавать
  флаг, пусть LM Studio решит сама». Без мостика значение уходит в поле
  `gpu: {ratio}` — в том же формате, что использует SDK LM Studio.
  Важно: на момент LM Studio 0.4 REST-API официально не принимает этот
  параметр ([issue #2566](https://github.com/lmstudio-ai/lmstudio-bug-tracker/issues/2566)).
  Если сервер отвечает 400, приложение автоматически повторяет загрузку без
  него, показывает предупреждение и готовую команду для Ubuntu, например:

  ```bash
  lms load 'qwen3-8b' --gpu 0.50
  # или: --gpu max, --gpu off
  ```

  Команду можно скопировать прямо из приложения. Если поле примет другой
  билд LM Studio, значение применится без предупреждения.
- **Flash Attention / KV-кэш на GPU** — три состояния: авто, включено,
  выключено. По умолчанию для новых чатов оба параметра **включены**;
  в существующих чатах можно оставить «авто» или выбрать вручную.
- **Eval batch size** — размер батча при загрузке; по умолчанию **2048**.
- **Загрузить / Перезагрузить / Выгрузить** — ручное управление памятью через
  `/api/v1/models/load` и `/api/v1/models/unload`. Если контекст уже
  загруженной модели отличается от выбранного, приложение подскажет нажать
  «Перезагрузить».

Контекст и параметры загрузки нельзя передать через OpenAI-совместимый
`/v1/chat/completions`, поэтому используются нативные методы LM Studio 0.4+.
На более старых версиях приложение автоматически откатывается к `/v1/models`
и серверной JIT-загрузке.

### Почему не все слои уходят на GPU

Если модель большая (например, Gemma), LM Studio при JIT-загрузке подбирает
оффлоад автоматически под свободную видеопамять. На 8–12 ГБ обычно получается
что-то вроде 38 из 42 слоёв: остальное остаётся на CPU, и это нормально —
модель работает, просто медленнее. Принудительно выставить `--gpu max` можно,
но при нехватке VRAM LM Studio может уменьшить оффлоад сам или загрузка
упадёт с OutOfMemory.

Проверить, сколько памяти займёт максимальный оффлоад, не загружая модель:

```bash
lms load 'google/gemma-3n-e4b' --gpu max --context-length 8192 --estimate-only
```

Если оценка больше свободной VRAM — уменьшите контекст, отключите KV-кэш на
GPU (`offload_kv_cache_to_gpu: false`), включите Flash Attention или возьмите
более компактное квантование. 42/42 не гарантируется: часть слоёв может не
поместиться физически.

### Плагин или MCP-сервер?

Ни то, ни другое не подходит для управления загрузкой:

- **MCP** в LM Studio даёт модели *инструменты* (функции, которые она вызывает
  во время ответа). У MCP-сервера нет доступа к загрузке/выгрузке моделей и
  к параметрам оффлоада.
- **Плагины** LM Studio (TypeScript, Node.js) — это хуки: tools-provider,
  prompt-preprocessor и generator. Generator подменяет *инференс* модели, но
  не участвует в её загрузке в память. Хука «перед загрузкой модели» в API
  плагинов нет.

Зато у CLI `lms` есть ровно то, что нужно: `lms load ... --gpu`. Поэтому
единственный надёжный путь — вызвать CLI на Ubuntu.

### Мостик к `lms` (HTTP)

В `tools/` лежит готовый мостик на стандартной библиотеке Python: он принимает
HTTP-запросы и выполняет `lms load` / `lms unload`. Токен обязателен, чтобы
никто в сети не мог выгружать ваши модели.

```bash
# на Ubuntu
sudo mkdir -p /opt/lm-gpu-bridge
sudo cp tools/lms_gpu_bridge.py /opt/lm-gpu-bridge/
BRIDGE_TOKEN='придумайте-длинный-токен' python3 /opt/lm-gpu-bridge/lms_gpu_bridge.py
```

Без `BRIDGE_TOKEN` мостик откажется слушать сетевой адрес (`0.0.0.0`):
разрешить пустой токен можно только на loopback-адресе (`BRIDGE_HOST=127.0.0.1`).

Проверка:

```bash
curl http://127.0.0.1:1235/health

curl -X POST http://192.168.1.50:1235/load \
  -H 'Authorization: Bearer придумайте-длинный-токен' \
  -H 'Content-Type: application/json' \
  -d '{"model":"google/gemma-3n-e4b","gpu":"max","context_length":8192}'
```

Эндпоинты: `GET /health`, `GET /ps`, `POST /load`, `POST /unload`,
`POST /estimate` (то же тело, что у `/load`, но с `--estimate-only`),
а также задания чата `POST /chat`, `GET /chat/<id>?since=N&wait=С`
и `POST /chat/<id>/cancel` (см. «Генерация в фоне»).
Самопроверка без LM Studio: `python3 tools/test_lms_gpu_bridge.py`.
Если LM Studio запущен на другом компьютере, задайте
`LMS_HOST=192.168.1.50:1234` — мостик добавит `--host` к командам `lms`
и будет проксировать туда чат.

Автозапуск: в `tools/lms-gpu-bridge.service` замените `__USER__` на
пользователя, который запускает LM Studio, затем создайте файл с токеном и
установите сервис:

```bash
sudo sh -c 'umask 077; echo "BRIDGE_TOKEN=$(openssl rand -hex 32)" > /etc/lm-gpu-bridge.env'
sudo cp tools/lms-gpu-bridge.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now lms-gpu-bridge
sudo systemctl status lms-gpu-bridge
```

Токен для приложения лежит в `/etc/lm-gpu-bridge.env` (только для root,
`chmod 600`). Токен и `LMS_API_KEY` не должны попадать в git.

Важно: если модель загружена не через мостик, а через JIT или REST, кнопка
«Перезагрузить» теперь сама перезагрузит её через мостик. Если указан явный
процент GPU, первое сообщение после запуска приложения тоже один раз
перезагрузит уже загруженную модель через мостик — чтобы принудительно
применить оффлоад. Дальше в течение сессии повторной загрузки не будет.

### Мостик в приложении

Мост включается для каждого сервера отдельно: **Настройки → сервер →
Изменить → «Включить мост»**. Адрес вводить не нужно: приложение берёт адрес
LM Studio и подставляет стандартный порт моста `1235`, например
`http://192.168.1.50:1235`. Остаётся ввести **«Токен моста»** (`BRIDGE_TOKEN`)
и при желании включить «Чат через мост». Кнопка «Проверить подключение»
проверяет и LM Studio, и мостик, и показывает версию `lms`.

Когда мостик задан:

- «Загрузить / Перезагрузить» и автозагрузка перед первым сообщением идут
  через `POST /load`; «Выгрузить» сначала пробует REST-выгрузку инстансов,
  а при ошибке — `POST /unload` мостика;
- `100%` → `--gpu max`, `CPU` → `--gpu off`, `25/50/75%` → `--gpu 0.25/0.50/0.75`;
- контекст и TTL передаются в `--context-length` и `--ttl`;
- `Авто` не передаёт `--gpu`, и LM Studio подбирает оффлоад сама;
- в разделе «Передача на GPU» появляется кнопка «Оценить память» — она
  вызывает `lms load --estimate-only` с текущими настройками и показывает
  оценку GPU/общей памяти до загрузки;
- Flash Attention, KV-кэш на GPU и eval batch size через мостик не
  передаются (в CLI для них нет флагов) — задайте их в LM Studio.

Если мостик не отвечает или вернул ошибку (например, не хватило VRAM),
приложение покажет текст ошибки и **не** станет молча грузить модель через
REST: иначе можно незаметно получить снова 38 слоёв. Уберите адрес мостика,
чтобы вернуться к обычной загрузке.

## Генерация в фоне

Android замораживает фоновые процессы: сокет перестаёт читаться, и ответ
обрывается, как только свернуть приложение. Приложение защищается двумя
способами.

### 1. Foreground-сервис

Пока идёт загрузка модели и генерация, работает foreground-сервис с
частичным wake lock. В шторке видно «LM Chat · Готовится ответ…». Это не
даёт системе заморозить процесс и держит сеть живой. Отключается
переключателем **Настройки → «Продолжать в фоне»**.

На Xiaomi/Redmi/POCO дополнительно:

1. **Настройки → Приложения → LM Chat → Батарея → «Без ограничений»**.
2. **Безопасность → Разрешения → Автозапуск** — включить.
3. Закрепите карточку LM Chat в списке недавних приложений.
4. **Для разработчиков → «Не сохранять активности»** — выключить.

### 2. Задания на мостике

Если у сервера указан мостик и включён переключатель **«Чат через мостик»**
(по умолчанию включён), запрос уходит не напрямую в LM Studio, а в
`POST /chat` мостика. Мостик сам читает SSE и складывает токены в буфер, а
приложение забирает их long-poll-запросами:

```
POST /chat        {"model": "...", "messages": [...], "job": "<id>"}
GET  /chat/<id>?since=7&wait=20
POST /chat/<id>/cancel
```

Что это даёт:

- ответ генерируется на Ubuntu и не зависит от телефона;
- свернул приложение, потерял Wi-Fi, даже убил процесс — генерация
  продолжается;
- при возврате приложение дочитывает пропущенные события с последнего `seq`;
- если процесс убили, при следующем запуске приложение находит сохранённый
  `jobId` и догружает ответ; если задание уже вычищено (TTL 60 минут),
  показывает «Ответ прерван», но сохраняет полученный текст;
- после обрыва сети в текущей сессии под ответом появляется кнопка
  «Догрузить ответ», а при возврате из фона приложение пробует догрузить
  автоматически.

Ограничения: задания живут в памяти мостика, после перезапуска сервиса они
теряются. Flash Attention, KV-кэш и batch size по-прежнему задаются в
LM Studio. Если мостик старый и `/chat` отвечает 404, приложение
автоматически переключается на прямой стрим и подсказывает обновить
`lms_gpu_bridge.py`.

Дополнительные переменные мостика:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LMS_API_KEY` | пусто | токен LM Studio, если включён |
| `BRIDGE_CHAT_TIMEOUT` | 1800 | сколько ждать токены от LM Studio |
| `BRIDGE_JOB_TTL` | 3600 | сколько хранить готовое задание |
| `BRIDGE_MAX_JOBS` | 8 | максимум заданий в памяти |
| `BRIDGE_MAX_EVENTS` | 20000 | максимум событий в одном задании |
| `BRIDGE_MAX_JOB_BYTES` | 67108864 | суммарный размер тел заданий в памяти |
| `BRIDGE_READ_TIMEOUT` | 30 | таймаут чтения тела запроса, секунды |
| `BRIDGE_MAX_LMS_OUTPUT` | 1048576 | максимум вывода `lms` |
| `BRIDGE_MAX_BODY` | 33554432 | максимальный размер тела запроса (для изображений) |

## Варианты ответа

Кнопка «Сгенерировать заново» больше не удаляет предыдущий ответ. Текущий
вариант сохраняется в самом сообщении (`versions` в `lm_chat_data.json`),
а новый стримится поверх:

- под ответом появляется строка `‹ Вариант 2 из 3 ›`;
- стрелки переключают варианты, кнопка со списком открывает все сохранённые
  ответы с датой, моделью и превью;
- в контекст модели уходит только выбранный вариант;
- удалить можно любой старый вариант, новый — только вместе с сообщением;
- если новая генерация упала или была остановлена без текста, приложение
  само возвращает предыдущий ответ и показывает причину;
- варианты хранятся без ограничения по количеству и попадают в экспорт JSON.

Ответ можно отредактировать вручную: кнопка с карандашом открывает редактор.
Сохранённый текст становится текущим ответом, а прежний уходит в варианты —
даже если редактировался старый вариант. Токены и скорость для
отредактированного текста не показываются (они относились к исходной
генерации); при переключении на старый вариант статистика снова видна.

```json
"versions": [
  {"id": "…", "content": "старый ответ", "model": "qwen3-8b",
   "createdAt": "2026-11-09T19:00:00.000"},
  {"id": "…", "content": "ещё один вариант", "model": "qwen3-8b"}
],
"activeVersion": 1
```

`activeVersion` — номер показанного варианта (1 — самый старый,
`versions.length + 1` — текущий). Старые файлы без этого поля читаются
как обычно.

## Скорость, токены и контекст

Под каждым готовым ответом появляется чип:

```
⚡ 24.3 tok/s · 8.4 с
```

Тап открывает карточку: модель, номер варианта, токены запроса, ответа и
всего, средняя скорость, общее время и занятость контекста.

Токены берутся из `usage`, который LM Studio возвращает при
`stream_options: {"include_usage": true}`. Если сервер не поддерживает этот
параметр, приложение повторяет запрос без него и считает токены
приблизительно — такие цифры помечены `≈`.

Над полем ввода — строка:

```
Контекст: осталось 14 336 из 32 768
```

- лимит: контекст из настроек запуска → контекст загруженного инстанса →
  `max_context_length` модели;
- занято: точный `prompt + completion` последнего ответа, а сообщения после
  него — оценка;
- полоса становится жёлтой при остатке меньше 20% и красной при меньше 10%;
- тап открывает расшифровку: занято, осталось, лимит и источник лимита.

Мостик отдаёт `usage` и `elapsed_ms` в `GET /chat/<id>`, поэтому статистика
сохраняется, даже если ответ дочитывается после перезапуска приложения.
Все цифры хранятся в `lm_chat_data.json` вместе с сообщением и его версиями.

## Переход на `app.lmchat`

Идентификатор приложения изменён на `app.lmchat`.
Android считает это новым приложением, поэтому старые чаты и токены не
переносятся автоматически. Перед установкой новой версии сделайте в старой
**экспорт истории** и **экспорт профиля**, затем импортируйте их в новой;
токены введите заново.

На Windows данные старой версии лежат в каталоге прежнего издателя
(`%APPDATA%\<старый издатель>\lm_chat`), новая версия использует
`%APPDATA%\LM Chat\lm_chat`. Перед первым запуском можно скопировать
`lm_chat_data.json` и `lm_chat_data.json.bak` в новый каталог. Токены лучше
ввести заново; при необходимости перенесите и `flutter_secure_storage.dat`
(он зашифрован DPAPI под текущего пользователя).

## Сборка APK

Требования: Flutter 3.47+, JDK 17+, Android SDK (platform 36, build-tools 36).

```bash
flutter pub get
flutter build apk --release
```

Готовый файл: `build/app/outputs/flutter-apk/app-release.apk`.

Компактные сборки под конкретную архитектуру:

```bash
flutter build apk --release --split-per-abi
```

- `app-arm64-v8a-release.apk` — почти все современные телефоны (~18 МБ);
- `app-armeabi-v7a-release.apk` — старые 32-битные устройства (~16 МБ);
- `app-x86_64-release.apk` — эмуляторы.

Копии готовых файлов лежат в `dist/`.

Установка на телефон:

```bash
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

или просто перекиньте APK на устройство и откройте (разрешите установку из
неизвестных источников).

Для публикации создайте собственный keystore и скопируйте
`android/key.properties.example` в `android/key.properties`, заполнив пароли
и путь к файлу. Без `key.properties` release-сборка **завершается ошибкой**:
debug-подпись больше не подставляется молча. Для локального
`flutter run --release` задайте `LMCHAT_ALLOW_DEBUG_SIGNING=1`.

Для автообновления все APK должны быть подписаны **одним и тем же ключом**.
Приложение перед установкой сравнивает сертификат скачанного APK с
установленным и отказывается от подмены. Windows-установщик проверяется через
Authenticode; неподписанный файл не запускается. Debug-ключ подходит только
для личных сборок.

## Сборка для Windows

Требования: Flutter 3.47+, Visual Studio с рабочей нагрузкой
«Разработка классических приложений на C++» и Windows 10 SDK.

```bash
flutter pub get
flutter build windows --release
```

Готовый комплект: `build/windows/x64/runner/Release/`. Запускайте
`lm_chat.exe` из этой папки — рядом должны лежать DLL и каталог `data/`.
Архив для переноса: `dist/lm-chat-windows-x64.zip`.

### Установщик

Для установки используется Inno Setup 6. Проще всего собрать всё одной
командой:

```powershell
.\tools\build_windows_installer.ps1
```

Скрипт берёт версию из `pubspec.yaml`, собирает Windows release и компилирует
`installer\lm_chat.iss`. Можно и вручную:

```powershell
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" "installer\lm_chat.iss"
```

Результат: `dist/lm-chat-setup-1.8.2.exe`.

- Устанавливается только для текущего пользователя, без UAC, в
  `%LOCALAPPDATA%\Programs\LM Chat`.
- Создаёт ярлык в меню «Пуск», опционально — на рабочем столе.
- Штатное удаление через «Приложения и возможности».
- История чатов и токены хранятся в профиле пользователя и при удалении
  приложения не затрагиваются.
- Установщик не подписан, поэтому SmartScreen может показать предупреждение
  при первом запуске. Для публикации задайте отпечаток сертификата:
  `$env:LMCHAT_SIGN_CERT="<sha1>"` перед запуском скрипта — он подпишет EXE
  через `signtool` с timestamp. Автообновление отказывается запускать
  неподписанный установщик.

## Сборка в сети без доступа к dl.google.com

В `android/settings.gradle.kts` и `android/build.gradle.kts` репозитории
`google()` заменены на зеркала Huawei Cloud и Tencent Nexus. Если у вас есть
прямой доступ к Google Maven, можно вернуть стандартный `google()`.

## Ограничения

- Только локальная сеть. Для доступа снаружи используйте Tailscale на ПК и
  телефоне (адрес `100.x.y.z:1234`), не открывая порт в интернет.
- HTTP без шифрования — подходит для доверенной домашней сети.
- Голосовой ввод использует системный сервис распознавания Android (обычно
  Google). Если на устройстве нет офлайн-пакета, аудио может отправляться в
  сеть Google; сами чаты и тексты в LM Studio при этом не пересылаются.
- GBNF-грамматика поддерживается llama.cpp-совместимыми серверами. LM Studio
  может проигнорировать поле `grammar` — для неё используйте JSON Schema.
