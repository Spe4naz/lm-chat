# Настройка LM Studio

## Сервер

1. **Developer → Start Server**. Порт по умолчанию — `1234`.
2. Включите **Serve on Local Network** (иначе сервер слушает только localhost).
3. По желанию включите **Require Authentication** и создайте API-токен.
4. Разрешите порт в файрволе:

   ```bash
   sudo ufw allow 1234/tcp
   sudo ufw status
   ```

Проверка с компьютера:

```bash
curl http://localhost:1234/v1/models
curl http://192.168.1.50:1234/v1/models
```

Вторая команда должна работать. Если нет — сервер слушает только localhost или
порт закрыт файрволом.

На Windows откройте TCP 1234 для профиля «Частная сеть»:

```powershell
New-NetFirewallRule -DisplayName "LM Studio" -Direction Inbound -Protocol TCP -LocalPort 1234 -Profile Private -Action Allow
```

## Headless Ubuntu

Без графического интерфейса LM Studio управляется через `lms`:

```bash
lms server start --bind 0.0.0.0 --port 1234
lms load <имя-модели>
lms server status
```

`--bind 0.0.0.0` равносилен «Serve on Local Network». Автозапуск настраивается
через systemd.

## Адрес в приложении

```
http://192.168.1.50:1234
```

Без `/v1`. HTTP допустим только для локальных адресов; для внешнего сервера
нужен HTTPS или Tailscale (`100.x.y.z`).

## Параметры запуска модели

Открываются иконкой памяти в шапке чата, через «Запуск модели», в «Параметрах
чата» и в значениях по умолчанию.

- **Контекстное окно** — пресеты до 262144 токенов и своё значение, ограниченное
  `max_context_length` модели. Больше контекста — больше памяти.
- **Загрузка по требованию** — при отправке сообщения приложение сразу стримит
  ответ, а LM Studio загружает модель сама. Если выключено, приложение заранее
  проверяет `/api/v1/models` и при необходимости загружает модель с выбранными
  параметрами.
- **TTL автовыгрузки** — `ttl` в секундах уходит вместе с запросом на генерацию.
  «Сервер» означает настройку LM Studio (обычно 60 минут).
- **Передача на GPU** — `CPU`, 25/50/75/100% или «Авто». С мостиком значения
  превращаются в `lms load --gpu off|0.25|…|max`; без мостика уходит поле
  `gpu: {ratio}`.
- **Flash Attention / KV-кэш на GPU** — авто, включено, выключено.
- **Eval batch size** — по умолчанию 2048.
- **Загрузить / Перезагрузить / Выгрузить** — через `/api/v1/models/load` и
  `/api/v1/models/unload`.

Контекст и параметры загрузки нельзя передать через OpenAI-совместимый
`/v1/chat/completions`, поэтому используются нативные методы LM Studio 0.4+.
На более старых версиях приложение откатывается к `/v1/models` и JIT-загрузке.

Если LM Studio отвечает 400 на поле `gpu`, приложение повторяет загрузку без
него, показывает предупреждение и готовую команду для Ubuntu:

```bash
lms load 'qwen3-8b' --gpu 0.50
```

## Почему не все слои уходят на GPU

LM Studio при JIT-загрузке подбирает оффлоад под свободную видеопамять. На
8–12 ГБ часто получается 38 из 42 слоёв: остальное остаётся на CPU, и это
нормально — модель работает, просто медленнее. `--gpu max` можно задать
принудительно, но при нехватке VRAM LM Studio уменьшит оффлоад сама или
загрузка упадёт с OutOfMemory.

Оценка памяти без загрузки:

```bash
lms load 'google/gemma-3n-e4b' --gpu max --context-length 8192 --estimate-only
```

Если оценка больше свободной VRAM — уменьшите контекст, отключите KV-кэш на
GPU, включите Flash Attention или возьмите более компактное квантование.

## Плагин или MCP?

Для управления загрузкой не подходит ни то, ни другое:

- **MCP** даёт модели инструменты, но не доступ к загрузке/выгрузке моделей и
  параметрам оффлоада.
- **Плагины** LM Studio — это хуки (tools-provider, prompt-preprocessor,
  generator). Хука «перед загрузкой модели» в API плагинов нет.

Единственный надёжный путь — CLI `lms` через мостик:
[Bridge](https://github.com/Spe4naz/lm-chat/wiki/Bridge).

## Доступ к компьютеру

Плагин [lm-computer](https://github.com/Spe4naz/lm-computer/wiki) даёт модели
файловые инструменты и `shell_run`. REST и MCP работают в отдельном сервисе на
портах `1236`/`1237`, потому что LM Studio выгружает процессы плагинов.
