# Безопасность

## Модель угроз

LM Chat рассчитан на доверенную домашнюю сеть: приложение и LM Studio находятся
в одной LAN, доступ к серверу по возможности закрыт токеном, наружу ничего не
публикуется. Отдельного облака и аккаунтов нет — все данные остаются на
устройстве и на компьютере с LM Studio.

Что приложение делает для защиты:

- API-токены и токены мостика хранятся в Android Keystore / Windows Credential
  Manager, а не в JSON;
- токены не попадают в экспорт истории и профиля;
- HTTP-адреса вне локальных диапазонов отклоняются с понятной ошибкой;
- символы перевода строки и управляющие символы в токенах отклоняются;
- импорт серверов из профиля проходит валидацию адресов;
- обновления проверяются по SHA-256 и подписи.

## Трафик по локальной сети

LM Studio по умолчанию работает по HTTP, поэтому чаты, токены и содержимое
файлов идут по LAN в cleartext. Это осознанный компромисс:

- `usesCleartextTraffic="true"` остаётся включённым, потому что Network Security
  Config не умеет выражать диапазоны RFC1918 (`192.168/16`, `10/8`,
  `172.16/12`);
- вместо этого `ServerConfig` разрешает HTTP только для локальных адресов и
  отклоняет публичные;
- для недоверенных сетей используйте Tailscale (адрес `100.64/10` считается
  локальным, но трафик шифруется WireGuard) или HTTPS reverse proxy.

Не открывайте порты LM Studio в интернет. Для доступа снаружи достаточно
Tailscale на компьютере и телефоне.

## Подпись и обновления

- Release APK собирается только при настроенном `android/key.properties`.
  Без него сборка падает: debug-ключ больше не подставляется молча.
- `LMCHAT_ALLOW_DEBUG_SIGNING=1` разрешает debug-подпись только для локальных
  сборок.
- Перед установкой APK приложение сравнивает сертификат скачанного файла с
  сертификатом установленного приложения. Подмена ключа невозможна.
- Windows-установщик проверяется через Authenticode; неподписанный EXE
  автообновление не запускает.
- Файл обновления должен называться `lm-chat-universal.apk` (Android) или
  `lm-chat-setup-*.exe` (Windows), скачивается только по HTTPS с GitHub и
  сверяется с SHA-256 из метаданных релиза или блока `SHA-256` в описании.

Debug-подписанные сборки не обновляются на release-сборки: Android не разрешает
смену ключа. Для личных сборок это нормально; для публикации нужен постоянный
keystore.

## Разрешения Android

| Разрешение | Зачем |
|---|---|
| `INTERNET` | запросы к LM Studio, мостику и GitHub |
| `WAKE_LOCK`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC` | генерация в фоне |
| `POST_NOTIFICATIONS` | уведомление foreground-сервиса |
| `RECORD_AUDIO` | голосовой ввод по кнопке микрофона |
| `REQUEST_INSTALL_PACKAGES` | установка скачанного APK при обновлении |

## Проверки в CI

Каждый push в оба репозитория запускает:

- **gitleaks** — поиск случайно закоммиченных секретов;
- **CodeQL** — статический анализ (Python в lm-chat);
- **OSV-Scanner** — уязвимые зависимости;
- **SBOM** — SPDX-отчёт о составе сборки;
- **dependency review** на pull request с порогом `high`.

Результаты видны в **Security → Code scanning**.

## Если токен утёк

1. В LM Studio пересоздайте API-токен (**Developer → Require Authentication**).
2. В приложении обновите токен сервера.
3. Для мостика: замените `BRIDGE_TOKEN` в `/etc/lm-gpu-bridge.env`, перезапустите
   `lms-gpu-bridge` и обновите токен в настройках сервера.
4. Для плагина: см. [lm-computer → Security](https://github.com/Spe4naz/lm-computer/wiki/Security).

## Сообщить об уязвимости

Не публикуйте рабочие токены и приватные ключи в issue. Опишите шаги
воспроизведения без секретов: версия приложения, версия LM Studio, платформа,
что происходит и что ожидалось. Если проблема критична, используйте приватный
канал GitHub (Security → Report a vulnerability).
